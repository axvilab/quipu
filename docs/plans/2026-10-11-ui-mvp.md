# UI MVP

Status: done · 2026-10-11

Goal: `quipu ui` opens a local web page with the data quipu already computes, so the user does
not have to remember CLI commands. Read-only first; "Apply" buttons come next. Layout follows the
mockup from 2026-10-10 (dark sidebar, project map, cache, advisor); the switchboard waits for
module 7.

Decisions (within ADR 0004):
- Server-rendered `html/template` pages and one CSS file, embedded with `go:embed`. No JS
  framework and no frontend build; a little vanilla JS only where a page needs it.
- System font stacks, no web fonts: the UI makes no network requests.
- Binds to 127.0.0.1 on a random port; a random token in the first URL becomes a cookie; requests
  with another Host header are refused. Opens the browser with `xdg-open` / `open`.
- The user's real data is the demo: findings stay unfixed until "Apply" exists.

1. [x] `internal/ui`: server, token, Host check, layout with sidebar.
2. [x] Overview: projects table (sessions, prompt, cache writes, hit rate, start weight).
3. [x] Project page: map (always / on demand, bars by weight), measured start weight, findings.
4. [x] Cache page: daily bars and miss reasons, 7 / 30 / 90 days.
5. [x] Advisor page: findings of all projects, identical ones grouped ("13 projects").
6. [x] `quipu ui` command; run on real data.

## Outcome

All four pages work on real data (9 projects, 16k requests); the slowest page renders in about
0.5 s. Grouping on the advisor page shows the synced-skills finding once for 9 projects.
Next: "Apply" buttons with a preview and backup, the switchboard (module 7), autostart of the
daemon, opening an already running UI instead of starting a second one.
