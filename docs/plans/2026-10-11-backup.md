# Backup and restore of the Claude Code setup

Status: done · 2026-10-11 · design in DESIGN.md §4.6

## Goal

Get the Claude Code setup back after an OS reinstall or on a new machine: one archive file, or
a private git repository the user trusts. Both are explicit actions; nothing is uploaded on its
own.

## Contents

Included, for every profile (`~/.claude`, `~/.claude-<name>`): `CLAUDE.md`, `settings.json`,
`rules/`, `skills/` (not `skills/synced/`, which claude.ai owns), `agents/`, `commands/`, and the
memory of each project (`projects/<project>/memory/`); quipu's `profiles.json`. Files a profile
shares with `~/.claude` through symlinks are recorded as links, not copied twice.

Never included: credentials, `.claude.json`, transcripts, caches, plugins, anything else.

## Layout

The same in the archive (`.tar.gz`) and in the repository, so restore reads either:

```
manifest.json            quipu version, time, original home, symlinks
claude/<profile>/...     files relative to the profile's config dir
quipu/profiles.json
```

Project memory folders are named after the project's absolute path; when the home folder differs
on restore, the names are rewritten for the new home.

## Safety

- A secret scan runs before every backup (API keys and tokens of common services, private keys,
  `password`/`token`/`secret` values in settings `env`). Anything found stops the backup with
  file and line; `--allow-secrets` includes it anyway, on purpose.
- Restore shows every file it would write (new, changed, unchanged) before writing, and writes
  through the journal: one batch, undone in one click.
- Git: quipu writes the files, commits locally and pushes only when asked; it uses the system git
  and never handles git credentials.
