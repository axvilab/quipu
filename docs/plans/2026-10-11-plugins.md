# Plugins: what they cost and whether they are used

Status: done · 2026-10-11 · first part of module 7 (DESIGN §4.7)

## Goal

An enabled plugin lists its skills, agents and commands, and its MCP tools, in every session of
every project it is enabled for. Show that cost per project, and propose fixes for plugins that
are enabled everywhere but used in one project, or not used at all.

## Usage

Collected from transcripts, per assistant response, into a new `plugins` column:

- a tool `mcp__plugin_<plugin>_<server>__<tool>` (a plugin's MCP server);
- the Skill tool with `skill: "<plugin>:<name>"`;
- a subagent with `subagent_type: "<plugin>:<name>"`;
- a slash command `/<plugin>:<name>` typed by the user (counted with the next response).

Claude Code writes one line per content block and repeats the message, so references are taken
from every line of a message, not only the first. Store files get a schema version in their
name (`.v2.parquet`): transcripts that still exist are collected again, files whose transcript is
gone stay readable without the column.

## Rules

| ID | Finds | Fix (one click, through the journal) |
|---|---|---|
| `unused-plugin` | a plugin enabled for the project and used in no project in 30 days (while there were sessions) | `enabledPlugins.<id>: false` where it is enabled |
| `plugin-one-project` | a plugin enabled in the user's settings and used in only one project in 30 days | disable it in the user's settings, enable it in that project's `settings.local.json` |

Savings count the plugin's skill, agent and command listings; MCP tool definitions also cost
tokens, but their size is known only to Claude Code, so it is mentioned, not counted.
