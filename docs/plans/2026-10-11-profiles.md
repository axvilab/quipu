# v0.1: profiles

Status: open · 2026-10-11

Goal: run Claude Code under the right subscription per folder (personal / work) without
`/logout` + `/login`, with an optional shared library of skills and rules.

Facts checked on Claude Code 2.1.296:
- `CLAUDE_CONFIG_DIR=<dir> claude auth status --json` reports `loggedIn`, `email`,
  `subscriptionType` for that dir: profile status without reading credentials.
- A fresh `CLAUDE_CONFIG_DIR` gets its own `.claude.json` inside the dir; `~/.claude` is untouched.

Decisions:
- The default profile is plain `~/.claude` with no env var. Others are `~/.claude-<name>`.
- quipu state lives in `~/.config/quipu/profiles.json`: profiles, shared items, folder rules.
- Shared library = symlinks inside the new profile dir to `~/.claude/{skills,agents,rules,commands,CLAUDE.md}`,
  chosen at `profile add`. `projects/` (memory, transcripts) is never shared: that is the
  personal / work boundary.
- `profile remove` deletes only the symlinks quipu made and the config entry; the profile dir
  (credentials, sessions) stays, its path is printed.
- `quipu run` picks: `--profile` → longest matching folder rule → ask (TTY, several profiles,
  interactive use) → default. Runs the real `claude` from PATH (skipping quipu itself) as a
  child, forwarding signals and the exit code.
- No shell rc edits and no `claude` symlink in this step; `alias claude='quipu run'` is suggested.

1. [x] `internal/profile`: config, add/remove with shared links, folder rules, resolve.
2. [x] Status through `claude auth status --json`; find the real claude; run with signals.
3. [x] CLI: `quipu profile list|add|remove|login`, `quipu profile rule add|remove`, `quipu run`.
4. [x] UI: profile list with login state in the sidebar.
5. [x] Tried on a demo home with a fake `claude`. [ ] On the real machine with the user, after the next release.

## Outcome

Works end to end on a demo home: profile with shared skills and CLAUDE.md, folder rule, explicit
`--profile`, default without a terminal, removal that keeps the login. Found and fixed: a refused
`add` left an empty dir; `/dev/null` was taken for a terminal (now `golang.org/x/term`).
Not verified yet with real Claude Code: whether it follows symlinked `skills/` in a non-default
config dir. Check on the real machine.

## Profiles page (added after v0.0.2)

Add, remove, folder rules and sign-in from the UI. Sign-in runs `claude auth login` with quipu
itself as `$BROWSER` (Claude Code honours it, checked on 2.1.296): the sign-in URL lands in a
0600 file and the page offers it as a link, so it works from a systemd service without access to
the desktop session. Claude completes the login through its own localhost callback; quipu never
sees credentials.
