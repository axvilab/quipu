# v0.1: collector and cache report

Status: done · 2026-10-11

Goal: `quipu cache` shows cache hit % per project and day from real transcripts.

1. [x] Spike: read a few real transcripts (read-only), write down the fields we need (usage,
   cache_read/cache_creation tokens, model, cwd, version). Build synthetic fixtures from them.
   Result: [transcript-format.md](../transcript-format.md). Usage repeats on every line of a
   response: dedupe by message ID. API reports cache miss reasons directly.
2. [x] `internal/claudecode`: discover profile config dirs; list transcripts; tolerant line parser.
3. [x] `internal/store`: DuckDB over Parquet (one file per transcript, atomic rewrite); CGO on.
4. [x] `internal/collect` + `quipu daemon [--once] [--interval]`: collects new or changed
   transcripts of all profiles; unchanged ones are skipped by modification time.
5. [x] `internal/analytics` + `quipu cache [--daily] [--project X] [--days N]`: per project or
   per day, plus API-reported miss reasons.
6. [x] Run on real data; decide whether to continue (see DESIGN §3).

## Outcome

Continue. On 30 days of real data (16k requests, 4.9B prompt tokens) the hit rate was 98.9% and
varied little between projects, so it is a weak signal. Useful signals: cache writes per project
(one project produced over half), very long sessions, and cache expiry after pauses as the main
miss reason. Next: `quipu map` to show what makes up the session start weight.
