# v0.1: project map

Status: open · 2026-10-11

Goal: `quipu map [path]` shows what Claude Code sends for a project: what is loaded into every
session, what only on demand, how many tokens each part weighs, and how that compares with the
measured start weight of real sessions.

1. [ ] `internal/claudecode`: find instruction sources of a project, following the documented
   loading rules:
   - always: user `CLAUDE.md`, `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` in the
     project and its parents, their `@imports` (up to 5 levels), rules without `paths:`,
     `MEMORY.md` (first 200 lines / 25 KB), name + description of every skill and agent
     (user, project, enabled plugins);
   - on demand: rules with `paths:`, skill and agent bodies, `CLAUDE.md` in subdirectories,
     other memory files.
2. [ ] Token estimate per item (no tokenizer locally: approximate, marked with `≈`).
3. [ ] Measured start weight from the store: prompt tokens of the first request of each main
   session (includes Claude Code's own system prompt and tools, which files cannot show).
4. [ ] `quipu map [path]`: grouped output, heaviest first, totals per group.
5. [ ] Run on real projects; note what the advisor (module 5) should flag.

Out of scope for now: MCP server tool lists (need `.claude.json`, read-only), plugin hooks,
output styles.
